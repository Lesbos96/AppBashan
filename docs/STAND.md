## Hinweise, die jede Session braucht
- Neue Dateien unter `tests/rls/` brauchen einen roten Lauf vor dem ersten grünen mit derselben Datei. Ein registriertes Skript (`scripts/setup-outbox.mjs` u. a.) braucht bei jeder Änderung eine Lösch-Freigabe über `advisor-report` und `npm run loesch -- uebernehme`; die Freigabe für `setup-outbox.mjs` (mail2) nennt Auflagen für einen Lauf. Jede Änderung von `scripts/sys/loesch-register.json`, `tests/support/**` oder `docs/freigaben/**` gehört in die Abnahme (Kontrollrunde).
- Neue Dateien direkt unter `scripts/`, die `dev-guard` importieren, brauchen einen Eintrag im Register (`ausgenommen` mit Grund und SHA-256), sonst wird `check` rot; ändert sich eine gepinnte Datei (`tests/support/positiv.ts`), den Pin nachführen.
- Nachweise nach `tmp/proof/` schreibt nur das Start-Programm oder Write (der Guard sperrt Umleitungen). Nie zwei Läufe gleichzeitig; ein abgebrochener Lauf lässt Kindprozesse und `tmp/proof/lauf.lock` stehen. Während der Pflichtläufe nichts bearbeiten (auch keine Docs).
- Edge Functions: `npx dotenv -e .env.local -- npx supabase functions deploy <namen> --use-api`; alle Functions deployen, die geänderte Dateien laden (`_shared/jobs/*` laden `accept`, `admin-contact`, `offer-confirm`, `outbox-send`; `_shared/photo/*` laden vier). Nach einer Migration, die `outbox_claim` ändert, `outbox-send` sofort nach `db:push` deployen. Smoke: 401 ohne Token, `functions list`; Deno: `npm run check:deno`.
