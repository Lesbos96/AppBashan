## Plan
1. **Register als reine Daten** in `tests/support/positiv-register.ts` (kein Import von `db.ts`, `owner.ts`, `vitest`): `REGISTER: Record<Name, Eintrag>` und `AUSNAHMEN: Record<Name, Grund>`. Name = `keyof Database['public']['Functions']`. Eintrag = { welt, als (`authenticated`|`service_role`|`anon`|`owner`), akteur?/aal?, aufruf (SQL-Argumente), ergebnis: `zeilen` mit `spalten` | `wert` mit pg-Typ | `leer` (void) }.
   - Zeilen-Funktionen: `spalten: { [C in keyof Row<N>]: PgTyp<Row<N>[C]> }` — der Typecheck bindet die Spaltenmenge und die Kategorie (Text, Zahl, Bool, Json, Array) an `Functions[N]['Returns']`; fehlt oder überzählig = tsc rot.
   - Wert-Funktionen: `typ: PgTyp<Returns>`.
   - Abweichung von der Aufgabe: Register liegt in `tests/support/`, nicht in `positiv.test.ts`, damit der Unit-Test es ohne Datenbankimport laden kann. `positiv.test.ts` enthält Aufbau und Aufrufe, nicht die Daten.
2. **Unit-Test** `tests/unit/positiv-register.test.ts`: liest die Funktionsnamen zur Laufzeit aus `database.types.ts` (Abschnitt zwischen `Functions: {` und `Enums: {`, Einzug 6), vergleicht mit `keys(REGISTER) ∪ keys(AUSNAHMEN)`: jede Funktion in genau einer Menge, keine Karteileichen, Ausnahmen haben nichtleeren Grund. Rot-Beweis: Eintrag entfernen → Unit-Test rot (Ist-Wert: Name der fehlenden Funktion in der Meldung), wieder einsetzen → grün; beides als Lauf über `npm run t`.
3. **`tests/rls/positiv.test.ts`**: in wenigen Welten (je ein `probes`-Aufruf = eine Rollback-Transaktion, ein CLI-Aufruf): Welt A Anfrage + Listings + Angebot + Bestätigung (Kundenwege, Partnerwege vor Zuschlag), Welt B angenommen + gestartet + Nachtrag, Welt C Storno-Wege, Welt D Admin/Preisversion/Partner-Verwaltung, Welt E Fotos/Outbox/Cron (service_role), Welt F Buchung/Mieten. Zerstörende Funktionen (delete_account, withdraw, cancel_*, complete_*) am Ende ihrer Welt. Je Eintrag: Schritt 1 als erlaubter Akteur ruft die Funktion (Zeilen: `create temp table … as select * from public.f(…)`), Schritt 2 als Eigentümer liest Anzahl und `pg_attribute`-Typen der Temp-Tabelle; erwartet ≥ 1 Zeile und exakt die registrierten Spaltentypen. Wert-Funktionen: `pg_typeof`. Void: Aufruf ohne Fehler.
   - Zusätzlich je Eintrag eine Katalogprüfung: der Akteur hat EXECUTE (`has_function_privilege`), damit „erlaubter Akteur“ gegen `pg_proc` gemessen wird und nicht nur gegen meine Annahme.
   - Ausnahmen (Funktion hat keinen Zeilen-Fall in Rollback-Welt, z. B. Cron ohne Vorlauf): Grund pro Eintrag.
