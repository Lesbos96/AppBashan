## 2. Bau
- `/partner` (bestehend): Firma laden (wie 5a). Statuskarte immer oben. Darunter je Status: `rejected`, `suspended`: nur Karte. `pending`, `active`, `payment_hold`: Schranke → ab `aal2` die Dokumente. (Portal-Funktionen jenseits Dokumente kommen in s9i-6; heute gibt es dahinter nichts.)
- Schranke (`mfa.ts`): `getAuthenticatorAssuranceLevel().currentLevel === 'aal2'` → durch; sonst `listFactors()`: verifizierter TOTP-Faktor vorhanden → Code-Abfrage (`challenge` + `verify`, sechs Ziffern, `autocomplete="one-time-code"`, `inputmode="numeric"`), keiner → Einrichtung (unverifizierte entfernen, `enroll`, QR aus `totp.qr_code` als `<img>` mit Alt-Text, Schlüssel als Text zum Abtippen, Code eingeben, `challenge` + `verify`). Nach `verify` setzt supabase-js die aal2-Sitzung selbst; die Schranke lädt neu.
- Fehlertexte: `mfa_verification_failed` „Der Code stimmt nicht“; 429 „Zu viele Versuche“; offline; sonst „Das hat nicht geklappt“. `insufficient_aal` bei `enroll` (zweites Gerät mit Faktor, nicht bei aal2): „Gib den Code deiner Authenticator-App ein.“ → zurück zur Code-Abfrage.
- Dokumente: Liste (`partner_documents`: Typ in Worten, Datum, „Hochgeladen“ oder „Datei fehlt“; ob die Datei liegt: `storage.list({partnerId})`), Auswahl Typ + Datei (`accept="application/pdf,image/*"`), Prüfung vor dem Senden: Bilder über `preparePhoto` (EXIF raus, JPEG, höchstens 2000 px), PDF höchstens 10 MB; Ablauf: Zeile anlegen (`id`, `kind`), dann `storage.upload('{partner_id}/{id}', blob, { contentType })` ohne `upsert`. Scheitert der Upload, bleibt die Zeile (Partner kann sie nicht löschen) und zählt gegen das Limit 5: die Liste zeigt „Datei fehlt“ mit „Erneut hochladen“ auf dieselbe `id`/denselben Pfad (kein Limit-Deadlock). Fehler: `limit_reached` (5 erreicht), `partner_not_active`, 42501 (kein aal2: zurück zur Schranke), zu groß, falscher Typ, offline.
- Bildsicht (S9i5-5): `npm run shots`-Muster für die Partner-Seiten bei 320, 390, 1280 px, `reviewer` per Bildsicht; Secrets in den Mocks sind Platzhalter.
